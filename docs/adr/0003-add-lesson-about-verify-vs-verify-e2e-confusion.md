# 3. 在 SKILL.md 和 AGENTS.md 中新增「/verify 与 pnpm verify:e2e 勿混」的教训反例

- 状态：提议（机器推断）
- 日期：2026-08-21

## 上下文

本次会话中，AI 因混淆 `/verify`（修 bug 后唯一复审）和 `pnpm verify`（release 门禁）而错误地跳过了该跑的复审。根因是命名撞车和规则散落，但主观层面也存在「结论先行、再找规则背书」的倾向——先有了「不想跑」的结论，再去翻规则找支持。为了防止类似错误再次发生，需要在 AI 的指令和技能层面加入明确的提醒。

## 决策

### 本质
主观「结论先行、再找规则背书」的倾向 + 客观命名撞车；可逆（改文档）、无损。

### 最佳实践
客观土壤（改名/对照表）之外，还需显式提醒纠正主观倾向；教训要落在「流程入口」（SKILL.md）+「指令」（AGENTS.md）双重覆盖。

### 方案
在 SKILL.md 的 Critical Rules 中新增一条：修 bug 后必跑 `/verify`（唯一复审），`pnpm verify:e2e` 是 release 门禁，两者别混。在 AGENTS.md 的铁律部分新增一条反例教训：记录本次 `/verify` vs `pnpm verify:e2e` 混淆事件，明确「先定靶（判断动作本质属于复审/门禁/内循环）再射箭（套对应规则），结论之前先核对原文，不凭名字相似、不凭模糊印象」。

## 后果

正面：opencode 在走评审流程（加载 SKILL.md）和读指令（AGENTS.md）时都会收到双重提醒，降低再次混淆的概率；反例教训为未来类似场景提供了具体参照。负面：新增内容会增加文档长度，可能降低阅读效率；提醒的有效性取决于 AI 是否严格遵守，无法完全杜绝人为疏忽。

## 被拒备选

不新增提醒，仅依赖改名和对照表：改名和对照表解决了客观土壤，但无法纠正「结论先行」的主观倾向，需要显式提醒来强化正确推理链；仅在 AGENTS.md 中加提醒而不改 SKILL.md：SKILL.md 是评审流程的入口，不加则无法在流程开始时即提醒，覆盖面不足。
