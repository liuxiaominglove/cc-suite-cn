# 15. 将 /fix 升级为完整五步闭环并新增第六步复审门控

- 状态：已接受
- 日期：2026-08-22

## 上下文

现有 /fix 缺少批判环节，/audit-full 缺少修复，无命令能独立走完找→批判→裁→修→验。且缺少修后复审纪律，导致用已修复掩盖未复审。

## 决策

### 本质
/fix 缺批判环节、无完整闭环、缺修后复审纪律；这是「流程」决策。

### 最佳实践
单一入口完整闭环（找→批判→裁→修→验）+ 复审门控防「用已修复掩盖未复审」。

### 方案
将 /fix 升级为找 bug→批判(qwen)→裁决(hy3)→终审修(opencode)→验证五步闭环，验证含编译测试、/verify 模型审 diff、真机测验和 UI 点验。第五步后硬暂停提交结果，询问用户是否进行第六步复审，同意后执行最终确认、保底和收尾。

## 后果

正面：单一入口完整闭环，批判环节防漏，复审门控防掩盖。负面：流程变长，需用户交互，可能增加等待时间。

## 被拒备选

将真机验证放在第六步复审：被拒，因用户明确要求真机测验和 UI 点验归入第五步验证，第六步仅做最终确认和收尾。
