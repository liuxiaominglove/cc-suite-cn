# 7. 自动复审只跑一次并列出现状后停止

- 状态：已接受
- 日期：2026-08-22

## 上下文

自动复审流程缺乏次数限制，可能无限循环；发现 bug 后自动修复和再审会掩盖问题，且消耗资源。需要明确规则防止重复审查同一 diff。

## 决策

### 本质
复审流程缺次数限制会无限循环、自动修复会掩盖问题；这是「流程」决策，可逆。

### 最佳实践
复审只自动跑 1 次；发现 bug 只列现状、不自动修/再审，修复由用户发起。

### 方案
自动复审只执行 1 次；发现 bug 只列出 finding 清单和 verdict 标记，不自动修复、不自动再审；修复与再审由用户显式发起。

## 后果

正面：避免无限循环，节省资源；用户对修复和再审有完全控制。负面：用户需手动发起再审，可能遗漏修复后的验证；流程依赖用户主动操作。

## 被拒备选

自动修复并再审：可能引入新问题且掩盖原始错误；无限次复审：浪费资源且无明确终止条件。
